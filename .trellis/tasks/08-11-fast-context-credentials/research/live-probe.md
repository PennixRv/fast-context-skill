# WSL Devin 运行探针

## 方法

在 WSL 的当前组件工作区执行 `env -u WINDSURF_API_KEY`，以当前组件为项目根、`--max-results 1` 为结果上限。探针将 CLI stdout/stderr 写入临时目录，只在同一受控进程内解析并输出退出码、JSON 存在性、结果状态、候选数量、截断布尔和固定 `FC_*` 代码；临时文件在退出时删除。

## 结果

格式修复后的首次探针以退出码 `0` 返回合法 JSON，状态为 `truncated`，候选数量为 `0`，没有 stderr 诊断。这证明在没有显式 `WINDSURF_API_KEY` 时，固定 Linux Devin 路径、受控辅助进程、JWT 获取、受限 Connect 请求和公开 JSON 输出均已贯通。

在补充一次同预算的工具格式重试后，使用同一有界查询的最终探针以退出码 `0` 返回合法 JSON，状态为 `truncated`，候选数量为 `1`，没有 stderr 诊断。候选路径和内容没有输出、写入任务或保留在临时文件外；`truncated` 继续表示本地预算/覆盖语义，不被描述为完整仓库搜索。

其他自然语言措辞仍可收到不符合严格工具参数语法的远端模型输出，并稳定失败关闭为 `FC_PROTOCOL_INVALID`。调试仅记录了请求阶段、严格 Connect 解码结论、工具标记存在性和语法布尔结论；未读取、打印、写入或摘要凭据、响应正文、候选路径、认证头、请求 ID、长度或摘要。Connect envelope 本身在该失败路径中仍通过严格解码，问题位于不可信工具参数格式。

## 处理与限制

实现补充了明确的工具标签提示，并仅允许标签之间的格式性空白；工具名、完整 JSON、工具 schema、PathGuard 和候选范围复核没有放宽。对于已通过严格 Connect 解码但工具标签/JSON 无效的响应，同一受限请求可在共享截止时间内重试一次；Connect/EndStream/压缩/输出上限仍立即失败。未采用上游的 JSON 修复、远端 prose 证据回收或桌面状态扫描。

由于用户先前原始 MCP 成功探针的精确查询文本没有保存在项目会话记忆中，本任务不声称复现了其完全相同的提示。离线回归和最终 WSL 探针均已证明合格的 Devin 值与符合协议的远端 answer 会经过本地范围复核并返回候选；根仓库仍应使用其保留的验收查询对已发布版本独立确认候选路径。

## 终结轮复核

实际探测曾连续耗尽三次 `restricted_exec` 轮次而没有 `answer`，因此稳定失败为 `FC_PROTOCOL_INVALID`。该现象不通过扩大本地命令轮次处理：客户端改为保留第四个、共享同一截止时间的 answer-only 请求，并在该轮仅声明 `answer`。

修改后的同一 WSL 命令再次以退出码 `0` 返回合法 JSON，状态为 `truncated`、候选数量为 `1`、无 stderr 和无 `FC_*` 诊断。探测进程始终使用 `env -u WINDSURF_API_KEY`；只输出退出状态、JSON 布尔、状态、数量和诊断类别。凭据、候选路径、响应正文、认证头、请求 ID、长度和摘要均未打印、写入或保留。
